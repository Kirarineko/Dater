# Dater 产品需求

更新日期：2026-10-06。

本文记录用户已裁定的产品行为，以及为后续实现提出的补充建议。首个可运行版本已经按下方范围实现；尚未覆盖的边界仍以“补充实现建议”和后续任务为准。

## 产品目标

Dater 是原创世界观日历管理终端应用（TUI），使用 TypeScript、OpenTUI Core、Bun 和 pnpm，采用 MIT 许可证。界面直接使用 OpenTUI Core 的 TypeScript API。

支持超大跨度年份的快速检索、自定义历法、现实农历对照、日程与节日管理，以及多个独立世界观。

世界观历法与农历各自使用自己的年月规则，通过基准日和连续天数建立对应关系。农历节日在世界观中的日期随映射变化，不固定按世界观的一年重复。

## 已裁定的需求

### 界面形态与技术方案

- 采用 OpenTUI 构建终端界面，替换原先的 Electron 桌面方案。
- 使用 OpenTUI Core 与纯 TypeScript，无需额外的 React 界面层。
- 键盘操作可完成年份检索、日历浏览、历法配置、日程编辑和世界观切换。
- 日历日期支持鼠标左键点选，保留现有键盘快捷键。
- 当日日程列表中按 `Esc` 返回日历；关闭对话框后恢复日历焦点，方向键与快捷键继续可用。
- 历法修改前的强制风险提示由终端内模态确认对话框实现。
- 世界观目录通过路径输入等终端交互方式设置，JSON 保存位置规则保持一致。
- 提供 `dater [世界观目录]` 终端命令并保留 `pnpm start`；无参数先检查终端当前目录，没有文件时再提示填写目录。

### 1. 年份与检索

- 允许负数年份与第 0 年；年份连续经过 -1、0、1。
- 支持通过输入框快速定位特定年份，适应原创世界观的大时间跨度。
- 不通过从起始年份逐年生成日历的方式实现大跨度检索。
- 数字月份和日号至少补齐两位，如 `01`、`02`、`09/27`；年份保持原样，超过两位的数字完整保留，JSON 数值结构不变。

### 2. 月份与星期

- 月份数量、每个月的天数均可独立设置。
- 启动时提供可编辑的现实公历默认值：12 个月，平年月份天数依次为 31、28、31、30、31、30、31、31、30、31、30、31。
- 默认采用完整公历闰年规则：能被 4 整除的年份为闰年，但能被 100 整除且不能被 400 整除的年份为平年；闰年二月为 29 天。
- 默认每周 7 天，星期数量与名称可修改。
- 年天数由月份配置和闰日分配确定；普通公历预设平年 365 天、闰年 366 天。

### 3. 闰年周期与闰日分配

- 支持固定闰年间隔。
- “闰年起始年”作为周期基准年，规则向过去与未来延伸。例如基准年为 3、间隔为 4，则 -5、-1、3、7、11 年均命中周期。
- 第一版允许将闰年增加的天数分配到一个或多个指定月份。
- 保留完整公历预设，不能以简单的每 4 年一次替代其世纪例外。

### 4. 强制闰年与平年

- 可单独指定某一年强制为闰年或平年。
- 支持规律性的强制闰年设置，包括年份数字匹配某个正则表达式时强制为闰年。
- 强制规则应与基础闰年规则、闰日分配配置共同作用。

### 5. 农历基准映射

- 农历对照在所选算法或数据源明确支持的范围内对应现实农历。
- 用户设置一个现实农历日期与一个世界观日期作为同一天，全部日期以此基准向前后推演。
- 现实农历基准须能唯一确定日期，包括具体年份、月份、日期，以及是否为闰月；仅使用每 60 年重复的干支年名不足以唯一确定年份。
- 映射以连续天数为基础，转换为世界观日期时自然跨越月份与年份。例如九月只有 29 天时，9 月 29 日之后为 10 月 1 日。
- 农历展示使用干支年与中文月日，闰月显示“闰”；干支年以农历正月初一换年。基准输入仍使用唯一的数字年份。
- 同时显示映射日的节气与传统民俗节日，去重后只读展示，不写入用户日程。选中日信息支持换行，窄终端可查看完整内容。

### 6. 农历支持范围与循环开关

- 允许世界观日期超过现实农历对照的支持范围。
- 关闭循环农历时，超出范围显示“农历不可用”，世界观日历及普通日程照常使用。
- 设置中提供可开关的循环农历。
- 开启后，超出范围后的第一个农历年作为循环第 1 年，重新从农历数据序列的开头计算，后续继续循环。
- 循环行为不改变世界观年份、月份、日程或基准日期。
- 循环农历是有限数据的重复推演；界面须明确标识，避免将循环结果表示为该日期的准确现实农历。
- 循环农历的日期、节气与节日使用同一个样本日计算。

### 7. 日程与节日

- 按常见日历产品提供普通日程管理，包括标题、备注、颜色、全天、定时、跨日、重复，以及重复日程的单次修改或取消。
- 支持世界观固定日期节日，以及按农历月份和日期确定的节日。
- 农历节日默认仅在普通月份出现，每条节日可单独开启闰月重复。
- 设置重复日程时，针对目标日期不存在的情况，可选择“跳过”或“顺延”。
- 顺延遵循世界观月份天数。例如九月仅有 29 天时，重复规则中的九月三十顺延至十月一日。
- 此处的无效日期处理针对重复规则；输入一次性日程的日期时应显示合法日期供选择或校验。

### 8. 修改历法后的日程

- 普通日程保留原世界观年月日；如果新历法中该日期不存在，按顺延处理。
- 农历节日依据修改后的世界观历法和农历基准重新计算。
- 修改应用前必须显示终端内模态风险提示，说明日程日期和农历映射可能受到影响，要求用户明确确认；取消则不应用修改。
- 风险提示应展示受影响的日程和前后日期，不能将变化静默应用。
- 历法修改造成的日程迁移与日程自身的重复规则是不同操作；迁移后的未来重复仍使用日程原有的“跳过/顺延”选项。

### 9. 世界观“今天”

- 不需要世界观“今天”、手动推进世界观时间或将世界观时间绑定现实日期的功能。
- 不自动引入依赖上述时间绑定的系统提醒。

### 10. 多世界观

- 支持创建与切换多个世界观。
- 每个世界观独立保存历法、农历基准、日程、节日及相关设置。
- 某个世界观的配置修改不影响其他世界观。
- 多世界观通过独立目录切换；切换前保存编辑，取消或读取失败时保留当前世界观。

### 11. JSON 保存位置

- 直接使用 JSON 文件持久化世界观数据。
- 每个世界观目录根部使用一个 `date.json`，保存全部历法、农历基准、日程与节日，保留内部稳定 ID 和格式版本。
- 世界观领域数据不得默认保存到应用安装目录或以数据库替代 JSON。
- 启动优先使用显式目录参数；无参数先检查终端当前目录。找到文件直接加载，没有文件才提示填写目录，填写后仍先加载已有配置，再进入首次创建。
- 不依赖软件内保存的目录记录；删除或重新安装软件后，指定原世界观目录仍能恢复其配置。
- 新文件使用 `date.json`；已有 `Date.json` 也可加载并沿用原路径，同时存在时优先 `date.json`。
- 固定文件不存在时检查旧 `dater_date/*.json`：一个有效世界观直接复制迁移，多个有效世界观显示名称和文件名供用户选择。保留旧文件与 ID，不合并数据。
- 旧文件均无法读取时报告错误并阻止静默新建；只有文件不存在时允许创建。格式损坏、无权限或超限时不得自动覆盖。

## 补充实现建议

以下约定用于补齐尚未逐项裁定的细节，可在后续任务中调整。不得将这些建议误记为用户已经明确选择的行为。

### 闰年规则优先级

建议按以下优先级判断某一年是否为闰年：

1. 单独指定该年份的强制闰年或强制平年设置。
2. 命中的正则强制闰年规则。
3. 固定间隔规则或完整公历预设。

同一年只允许一个单独覆盖值；多个正则命中同一年只将它判定为一次闰年，不重复增加闰日。是否为闰年与闰日分配分开保存。

正则输入建议使用年份的规范十进制字符串：负年带负号，第 0 年表示为 0，不包含前导零。匹配采用普通正则语义；需要匹配完整年份时由用户使用起止锚点。

大跨度跳转需要高效累计历史闰日数量。任意 JavaScript 正则不一定支持快速累计计数，回溯引用等特性也不适合直接用于该计算。后续应明确支持的正则语法，提供规则验证与命中预览，对无法高效计算的规则给出明确反馈。不能为实现正则支持而退回逐年扫描或阻塞界面。

### 循环农历的边界

建议默认关闭循环农历，开启后将所支持的完整农历年数据作为一个连续周期，按整个周期的总天数循环。

- 支持范围内仍显示真实农历对照。
- 正向超过最后一个完整农历年时，下一个农历新年进入循环第 1 年，采用数据序列第一个完整农历年的月份、闰月和天数。
- 第 1 年的长度按样本数据确定，后续采用第 2、3 年的数据；完整周期结束后再次回到第 1 年。
- 建议向过去越界时也循环，从周期末尾向前推算。
- “循环第 1 年”是数据周期内的年号，不是世界观第 1 年，也不是宣称真实农历公元 1 年。
- 正向与反向映射均维持一天接一天的连续关系，不通过直接取模世界观年份或固定每年天数来替代农历数据。
- 开关循环农历会影响超出范围的农历节日；应预览相关变化。

映射基准建议始终取自真实支持范围内，以使开启或关闭循环不改变基准的意义。当前源使用完整 1900–2100 农历年；循环显示样本日的干支年月日并明确标识循环年号。

### 无效日期与闰月日程

建议将“顺延”定义为从目标月份第 1 天开始，按目标日序数计数；溢出的天数继续进入后续月份，必要时跨年。

闰月重复建议仅在该年存在同名闰月时追加一次日程。普通月份和闰月中日期不存在时，分别应用该条日程选择的跳过或顺延规则。

### 保存与数据完整性

- 一个世界观目录对应一个根部 JSON 文件；显示名称重命名时保持内部 ID 不变。
- 支持大跨度的年份与连续日序号以十进制字符串写入 JSON，避免超过安全整数范围时产生精度丢失。
- 文件保存包含格式版本，便于未来迁移。
- 自动保存通过同目录临时文件和替换方式完成，避免写入中断破坏原文件。
- 读取时校验文件结构；保存失败时保留当前编辑内容并明确提示，不能显示已保存。
- 用户世界观数据为本地文件，不能提交到源码仓库；不引入启动所必需的软件内部目录列表。

## 后续验证重点

- 负年、第 0 年与正年的连续换算。
- 固定闰年周期向过去延伸，以及手工覆盖、正则规则与公历预设的组合。
- 闰日分配到多个不同月份后的年长度、日期转换和星期推进。
- 超大年份定位的精度与响应速度。
- 农历基准双向换算、闰月、支持边界及循环周期衔接。
- 重复日程的跳过、顺延与单次例外。
- 修改历法时终端风险确认对话框、迁移结果以及取消后的数据状态。
- 多世界观隔离、JSON 精度、保存位置和失败恢复。
- 当前目录与显式目录启动、Ctrl+C 后重启、旧数据迁移，以及软件重新安装后仅凭世界观文件恢复。
- 农历干支换年、节气、传统民俗节日、循环样本一致性及数字日期补零。
- 终端尺寸变化、中文显示宽度、焦点与键盘导航，以及退出后的终端状态恢复。

## 当前实现约定

首个可运行版本已实现终端界面、日历计算、农历基准、日程/节日、迁移预览和世界观 JSON 保存。当前采用上述建议中的闰年优先级、双向农历循环、稳定 ID 和十进制字符串保存；这些是实现约定，不改写为用户已逐项裁定的需求。

农历源选用 MIT 许可的 `lunar-typescript` 1.8.6，应用仅使用完整 1900–2100 农历年。正则采用有限自动机与十进制计数，不按年份逐年遍历；支持语法、复杂度限制和预览范围详见 [README](../README.md)。
